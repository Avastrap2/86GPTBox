# IBM PC 730/750 Type 6877/6887 firmware notes

## Scope and source identity

This note records evidence used by the 86GPTBox implementation. It treats data in the firmware and manuals as technical evidence, not as instructions.

- IBM Technical Information Manual `52h3381.pdf`, First Edition, June 1996
- System firmware `LQKT47A.BIN`, 262144 bytes, SHA256 `9bea0ded18cc5135f05ab1264882be28beb7fa2f20419390d3828692b1894afb`
- IBM updater package `lqjt44a.exe`, SHA256 `931edf0c7b0f374b5defee9ccdd3713fed1361bd4bc671fa1713fdf970c1900`

The manual and firmware apply to IBM PC 730 Type 6877 and IBM PC 750 Type 6887. They must not be used as a board specification for Type 6885.

## Implementation platform model

- Intel Pentium P54C, 50 MHz to 66.667 MHz bus, 1.5x to 2.5x multiplier
- Intel 430HX host bridge (strong inference) and Intel 82371SB PIIX3
- National Semiconductor PC87306 Super I/O at configuration ports 02Eh/02Fh
- S3 86C765 Trio64V+ at PCI 00:08.0 with 2 MiB EDO video memory
- PCI expansion positions 00:06.0, 00:07.0 and 00:0C.0
- 128 MiB maximum system memory
- 256 KiB standard L2 cache and 512 KiB optional L2 cache
- 93C46 EEPROM in 64 x 16-bit organization
- 8 KiB riser SRAM/NVRAM at ports 74h-76h

## Flash mapping

The physical Flash contains two 128 KiB banks. Only one bank is visible in the System ROM windows at E0000h-FFFFFh and FFFE0000h-FFFFFFFFh.

The reset state selects physical bank 1. Early POST configures PC87306 GPIO at 78h/79h, then changes GPIO 78h from 3Fh to 2Fh. Execution continues at the same F-segment offset in physical bank 0; both banks contain matching bootstrap code at this transition. POST 20h later toggles GPIO 78h bit 4 while staging both 128 KiB banks in RAM. Connecting A17 to GPIO 79h instead produces two copies of bank 0 and an invalid staged module header. These runtime results establish GPIO 78h bit 4 as Flash A17.

Changing the active bank also updates both direct-execution pointers and flushes the CPU translation cache. Updating only the data-read handler leaves cached instruction fetches on the previous bank.

## GPIO wiring

GPIO 78h:

- bits 1:0 are multiplier straps (strong inference)
- the working encodings are `01b` for 1.5x, `10b` for 2.0x and `00b` for 2.5x
- bit 4 drives Flash A17
- the remaining higher bits are output latches used by early chipset and board control code

GPIO 79h:

- bit 7: EEPROM access/password configuration input, healthy state high
- bit 4: 93C46 DI
- bit 3: 93C46 CLK
- bit 2: 93C46 CS
- bit 1: 93C46 DO
- bit 0: board status input, healthy state high; exact electrical name remains unknown

## Board I/O

- 48h: Rapid Resume command/data nibbles
- 49h bit 0: Rapid Resume ready/acknowledge
- 77h: optional Data Collaboration Card presence; FFh means absent
- 7Ch bits 3:0: L2 cache identity; 0Bh is the standard 256 KiB configuration
- 7Ch bit 6: chassis/tamper status, healthy state clear
- 7Dh bits 7:4: PCI interrupt-to-SMI mask
- 94h and 102h-105h: IBM board setup/POS-style registers

Rapid Resume presence detection requires a high-to-low transition on 49h bit 0. Returning a constant ready value does not pass the firmware check. The current model implements the transport-level transition and nibble acceptance, but does not claim command-level standby or wake fidelity.

A Windows 95 APM shutdown trace sends Rapid Resume commands 15h, 04h and 0Eh. Command 0Eh is the terminal power-supply Off request: on hardware, power is removed before the BIOS reaches its KBC-reset fallback. The model therefore maps a completed 0Eh command to emulator soft power-off.

## Persistent state

The riser SRAM interface is byte-addressed with 74h as address low, 75h as address high and 76h as data. Address bits are limited to 13, giving 8192 bytes.

Known riser firmware markers:

- offset 0186h bit 6 clear: NVRAM not marked corrupt
- offset 018Ah: 6Dh
- offset 018Bh: B6h
- offset 0500h: little-endian record length
- offset 0502h: additive 8-bit checksum byte

The emulator seeds only confirmed riser markers for a new NVRAM file. Unknown factory identity fields and undocumented riser CRC regions are not fabricated.

The valid empty 93C46 state uses word 07h = D5B6h, words 08h-27h = 0000h and status word 28h = 0000h. Word 07h is UPD CRC #1 over words 08h-28h. The firmware routine used when updating word 07h computes the CRC with a healthy zero status word; therefore seeding word 28h as FFFCh makes the next validation fail with POST 175. Setup can advance that invalid status to FFF8h, which explains the failure after saving and performing a hard reset.

An erased password block separately produces POST 177. The emulator repairs an erased block, its known partial initialization state, or the canonical empty state. It also normalizes the two invalid status values produced by the former emulator seed, FFFCh and FFF8h, to 0000h. Non-empty password and UPD data are otherwise preserved.

IBM POST also validates three planar CMOS records:

- standard additive checksum over 10h-2Dh, stored at 2Eh-2Fh
- additive checksum over 35h-3Dh, stored at 3Eh-3Fh
- IBM CRC-16 record beginning with its length byte at 42h, stored at 40h-41h

The canonical empty variable record is E1h F0h 00h at 40h-42h. A generic blank CMOS fails this CRC and sets diagnostic register 0Eh bit 6, which later causes POST 184. New IBM PC 700 CMOS state is seeded with all three valid empty records. An existing state is repaired only when the checksum-failure bits and the remaining blank-record signature identify this same initialization failure.

## Implemented boundary

The machine implementation includes banked read mapping, both System ROM aliases, PCI topology and swizzling, onboard S3 video, PC87306 GPIO wiring, 93C46 line-level behavior, validated empty security and UPD storage, persistent riser NVRAM, IBM CMOS checksums, documented board I/O defaults and the Rapid Resume transport handshake.

A clean 16 MiB configuration runs from reset code 80h through the main POST sequence, including 20h bank staging, 21h module processing, 70h-76h late initialization and the final 79h boot path. Storage boot, Windows 95 APM shutdown and a DOS Ctrl+Alt+Del warm reboot were also validated. The warm-reboot test exposed a host-injected-key cleanup bug: when POST reset the keyboard during the 50 ms Ctrl+Alt+Del sequence, stale break events caused a DOS interrupt-stack overflow. Reset-time key cleanup now clears those states without emitting scan codes.

The following remain deliberately conservative because neither the manual nor static firmware analysis establishes their full semantics:

- factory 93C46 contents and field meanings outside the confirmed empty security region
- all riser NVRAM CRC polynomials and factory data
- 7Ch bit 0 electrical function
- 7Dh low-nibble function
- detailed 7Eh/7Fh behavior
- all 102h-105h status bits
- Rapid Resume standby transitions and wake sources
- Flash erase/program commands and updated-image persistence
- optional 512 KiB L2 cache selection
- parity and diagnostic fault injection

These items require a real-machine register trace, factory EEPROM/NVRAM image, or board schematic for hardware-level closure. The implemented subset is sufficient for the validated firmware POST path; Setup, storage boot and APM behavior still require dedicated tests.
